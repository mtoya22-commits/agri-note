# 畑ノート v4.3

畝と区画の作付けから「今週やること」と作業手順を自動で出す、家庭菜園の記録アプリです。
記録はスマホに保存され、Googleスプレッドシートと自動で同期されます（複数の端末でも使えます）。

---

## 1. GitHub Pages に置く

1. GitHub で新しいリポジトリを作る（例：`hatake-note`、Public）
2. 次のファイルをアップロードする

   | ファイル | 役割 |
   |---|---|
   | `index.html` | アプリの画面 |
   | `app.js` | アプリの動き |
   | `crops.json` | 作物データ（19種）と霜の平年値 |
   | `sw.js` | 電波がなくても開けるようにする |
   | `manifest.webmanifest` | ホーム画面に追加したときの設定 |
   | `icon-192.png` `icon-512.png` `apple-touch-icon.png` | アイコン |

   `gas/` `src/` `build.js` は置いても置かなくても動作に影響しません（あとで直すときに便利です）。

3. リポジトリの **Settings → Pages** で Source：**Deploy from a branch**、Branch：**main / (root)** → Save
4. 1〜2分で `https://mtoya22-commits.github.io/hatake-note/` のようなURLで開けます

## 2. iPhoneのホーム画面に追加する

Safari で上のURLを開き、共有ボタン → **ホーム画面に追加**。以後はホーム画面のアイコンから開きます。
全画面のアプリとして動き、Safari のタブで開くより保存データが消えにくくなります。

## 3. Googleスプレッドシートとつなぐ（最初の1回だけ）

### スクリプトを用意する

1. Googleドライブで **新しいスプレッドシート** を作る（名前は「畑ノート記録」など）
2. メニューの **拡張機能 → Apps Script** を開く
3. 最初から入っている `function myFunction() {…}` を消して、`gas/Code.gs` の中身をすべて貼り付けて保存

### ウェブアプリとして公開する

1. 右上の **デプロイ → 新しいデプロイ** → 歯車 → **ウェブアプリ**
2. 次のユーザーとして実行：**自分**／アクセスできるユーザー：**全員** → **デプロイ**
3. 「アクセスを承認」→ 自分のアカウントを選ぶ
4. 「このアプリは Google で確認されていません」と出たら **詳細 → 〇〇（安全ではないページ）に移動 → 許可**
   （自分で作ったスクリプトなので問題ありません。このスプレッドシートにだけ書き込みます）
5. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピー

### アプリに貼る

畑ノートの **設定** → 「保存先のURL」に貼って **保存してつなぐ**。状態が「同期済み」になれば完了です。

- 2台目の端末（PCやタブレット）も、同じURLを貼るだけで同じ記録が見られます
- 機種変更のときも同じです。URLが分からなくなったら Apps Script の **デプロイ → デプロイを管理** で確認できます
- URLは合鍵の役割をします。人に見せたり、GitHub のファイルに書いたりしないでください

### スプレッドシートの中身

| シート | 内容 |
|---|---|
| `plantings` | 作付け（区画・作物・植えた日・終了日・メモ） |
| `logs` | 作業と収穫（1回の記録が1行。同じ日の収穫も別の行） |
| `frost` | 霜リスクの夜の予報と、翌朝の「霜あり／なし」 |
| `settings` | 作る作物・補正の設定 |

- 集計やグラフは **別のシート** で行ってください（ピボットテーブルなど）
- `deletedAt` に値がある行は、アプリで削除した行です。集計ではフィルタで外してください
- 数字やメモを **シート上で直接直してもかまいません**。直した行は自動で版（version）が上がり、各端末に反映されます
- 右端の4列（`updatedAt` `deletedAt` `version` `changeSeq`）は同期用です。触ろうとすると警告が出ます
- 1行目の見出しと列の並びは変えないでください

### 同期のしくみ（困ったときのために）

- 変更はまず端末に保存し、つながったときに送ります（畑で電波がなくても記録できます）
- アプリを開いたときに、スプレッドシートの全件を取り込みます
- 2台の端末（またはシートの手修正）で同じ行を変えていた場合は、**あとから変えた方** を残します
  （行単位なので、同じ作付けの別の項目を2台で同時に直した場合、古い方の変更は消えます）
- どうしても合わなくなったら、設定の **スプレッドシートから作り直す** で端末の内容を作り直せます

## 4. 作物データを直す

`crops.json` を GitHub 上で直接編集できます（鉛筆アイコン）。

| 項目 | 意味 |
|---|---|
| `start.window` | 植え付け・播種の適期（`"5中"` ＝5月中旬）。中間地の標準 |
| `start.notBefore` | 霜に弱い作物は「終霜から何日後以降」（`{"anchor":"lastFrost","days":14}`） |
| `tasks[].trigger` | `offset`：植えた日から◯日後（マイナスは準備作業）／`calendar`：暦で固定 |
| `trigger.repeat` | `everyDays` 日ごとに、`untilDays` 日目まで繰り返す |
| `trigger.notAfter` | 霜の前に終える作業（さつまいもの掘り上げ：初霜の7日前まで） |
| `frostKilled` | 初霜で枯れる作物。収穫期と見回りは初霜で打ち切り |
| `rotation` | 同じ区画で同じ科を作るまでの年数の幅と出典。`minYears` 未満＝連作リスク高、`maxYears` 未満＝推奨より短い |
| `routine` | 見回り系。まとめて完了でき、遅れ表示しない |
| `slotsNeeded` | 必要な区画数（1区画＝1/4畝） |
| `region` | 霜の平年値（初霜 11/24・終霜 4/1、気象庁 岐阜地方気象台）と予報地点 |

`"` や `,` の抜けがあると読み込めなくなります。保存前に [JSONの検証サイト](https://jsonlint.com/) で確かめると安全です。

### 連作年数の出典

作物ごとに `rotation.source` に記載しています。資料によって年数がかなり違うため、1つの資料を主に採用しています。

- 岡山県「野菜の年間栽培計画をたてよう！」：トマト・ナス・ピーマン・枝豆 4〜5年、キャベツ・イチゴ 2年、ほうれん草・レタス 1年、大根・にんじん・カブ・玉ねぎ 連作の害が少ない
- JA秋田ふるさと 営農ワンポイントアドバイス（2024年10月）：オクラ 1〜2年、スイカ 6〜7年、さつまいも・トウモロコシ 連作障害が少ない（トマト・ナスは6〜7年としている）
- アタリヤ農園「連作障害と輪作」：ブロッコリー 1年
- バジルは出典が見つからず暫定値（1年）です

### 霜の安全幅について

霜に弱い作物の植え付けを「平年の終霜から14日後以降」、掘り上げを「初霜の7日前まで」としているのは、アプリの暫定の安全幅です（出典なし）。
なお、タキイ種苗は夏野菜の定植の目安を「晩霜の心配がなく最低気温10℃以上、最低地温15℃以上」としています。多くの年は、中間地の適期（5月上〜中旬）がこれに先に当たります。

## 5. アプリを更新したとき

`sw.js` の1行目 `CACHE = "hatake-note-v4.3"` の番号を1つ上げてからアップロードしてください。

## 6. 霜リスクについて

- 各務原市の1時間ごとの予報（[Open-Meteo](https://open-meteo.com/)・無料・登録不要）から、夜ごとの最低気温・夜明け前の雲量と風速を見て判定します
  - **高**：最低1℃以下、または 3℃以下で「晴れ（雲30%以下）・弱風（2m/s以下）」
  - **中**：最低3℃以下、または 5℃以下で「晴れ・弱風」
  - この目安は暫定です。晴れて風の弱い夜は放射冷却で、地面近くが予報気温より冷えやすくなります
- 霜に弱い作物が植わっていて、7日以内に中・高の夜があるときだけ「今週」タブに出ます
- 中・高の夜は、前の晩の予報をそのまま保存します。翌朝に1回だけ「霜は降りていましたか？」と聞きます
- 答えは「記録」タブの **霜の記録** とスプレッドシートの `frost` シートにたまります。たまったら判定の見直しに使えます

## 7. 適期を過ぎた作物・作付けの始め方

### 時期の状態

| 表示 | 意味 |
|---|---|
| **適期中** | 中間地の適期（補正・霜の制約をかけたもの） |
| **遅め** | 適期は過ぎたが、`lateUntil` までは始められる。「作付けの適期」に残り、「今から始める」で登録できる |
| **◯日後** | 次の適期まで60日以内 |
| **今季非推奨** | それ以外。適期の一覧には出ないが、区画から選べば登録できる（初期の日付は次の適期の初日） |

`lateUntil` を入れているのは、資料で確認できた4作物だけです（`start.lateSource` に出典）。

| 作物 | 遅めの期限 | 出典 |
|---|---|---|
| 大根 | 9月下旬 | サカタのタネ「冬自慢」一般地・暖地 9月上旬〜下旬まき（品種による） |
| ブロッコリー | 9月下旬（植えつけ） | JA西春日井 家庭菜園：植えつけ 8月下旬〜9月下旬 |
| 晩生玉ねぎ | 12月上旬（植えつけ） | JA西春日井 家庭菜園：中生〜中晩生 11月中旬〜12月上旬 |
| ほうれん草 | 11月下旬 | 群馬県 ぐんまアグリネット（品種により8月上旬〜3月中旬まき）。11月下旬はアプリの控えめな区切り。寒い時期は保温 |

にんじん（JA西春日井：7月中旬〜8月中旬＝今の適期と同じ）、カブ・リーフレタス・キャベツ（はっきりした期限が見つからず）は、適期を過ぎると「今季非推奨」になります。

### 登録＝計画、開始作業の完了＝実際のスタート

- 作付けを登録しただけでは、播種・定植は完了になりません。今週のやることに残ります
- 登録する日付が今日以前のときは「これからまく／もうまいた」を選びます（過去の日付は「もうまいた」、今日は「これからまく」が初期値）
- 播種・定植を「完了」にするとき、実施した日を選べます。**その日から**、間引き・追肥・収穫などを計算し直します
- 予定日を過ぎても未実施のときは「開始待ち」に出し、その後の作業はまだ出しません
- 開始が遅れると、区画を使う期間の終わりも後ろにずれます。次の作付けの予約と重なったら「区画の予定が重なっています」と出ます

### 事前準備の確認

予定日より前に済ませておくはずだった準備作業（土づくりなど）が過ぎてしまった場合は、「遅れ」として出さずに、播種・定植の手順画面の上に「事前準備の確認」としてまとめます。

- 初期値では **「本来は播種の21日前ごろの工程」という情報として見せるだけ** です。今からそのまま行えという意味にはしません（石灰の「2週間置く」など）
- 本来の手順は「本来の手順を見る」を開くと確認できます
- 作業ごとに `lateStart` で扱いを指定できます（資料で確認してから入れる想定です）

| `lateStart.mode` | 表示 |
|---|---|
| `noteOnly`（初期値） | 本来の工程として情報だけ見せる |
| `doNow` | 「今からでもやること」として `doNow` の手順を見せる |
| `skip` | 表示しない |

`message` を入れると、その一言も表示します。例：`"lateStart": {"mode":"doNow","message":"播く前に畝だけは作る","doNow":["畝を立てて表面をならす"]}`

### 生育期間が足りない見込み

遅れて始めた場合も霜の制約は無視しません。霜で枯れる作物で収穫開始の見込みが平年の初霜より後になるとき、さつまいもで掘り上げの期限までに育ちきらないときは、強い警告を出します（登録はできます）。

## 8. 週1〜2回の畑通いに合わせた表示

日付は「締め切り」ではなく「目安」です。保存する日付（実際にまいた日・間引いた日・収穫した日）は正確に残し、判断のほうに幅を持たせています。

### 作業の種類と許容幅

作業の種類は作業名ではなく、作物データの項目から決めています。日数はアプリの初期値（出典なし）で、作業ごとの `timing: {"earlyDays":…, "lateDays":…}` で上書きできます。

| 種類 | 決め方 | 目安日の前 | 目安日の後 |
|---|---|---|---|
| 開始（播種・定植） | 植えた日から0日の作業 | — | 予定日を過ぎたら「開始待ち」 |
| 準備 | 植えた日より前の作業 | 3日 | 7日（それより前のものは「始める前に確認」へ） |
| 管理 | 間引き・追肥・土寄せ・誘引・整枝など | 3日 | 7日 |
| 収穫（1回きり） | 繰り返さない収穫 | 3日 | 7日 |
| 期限つき | `notAfter` がある作業 | 7日 | 期限の日まで |

- 許容幅は **期限を越えません**（許容幅 ∩ 期限）。例：玉ねぎの止め肥は、注意書きの「3月以降の追肥は厳禁」を期限（2月末）としてデータに入れました
- `urgency: "high"` の作業（今は期限つきの作業）は、個別の指定がなければ許容幅を短くします
- 見回り系と収穫期は、これまでどおり「遅れ」扱いにしません

### 生育段階がある作業

「本葉1〜2枚」などの段階がある作業は、日付を **確認を始める目安**、段階を **実施する条件** として表示します（例：`間引き1回目　9/30ごろ〜・本葉1〜2枚になったら`）。日付を過ぎても「遅れ」にはしません。

許容幅（初期値は目安日の7日後）を過ぎても未完了のときは、「遅れ」とは断定せずに **「生育を確認」** と表示し、「予定の時期を過ぎています。今の生育を確認してください」と案内します。目安日から3週間を過ぎると、ほかの作業と同じく「見送り」にできる一覧に移ります。

### 収穫期と収穫の頻度

収穫期に入っている作物は、次の収穫日にかかわらず「収穫期」に並びます。収穫の繰り返し間隔（`repeat.everyDays`）が7日より短い作物は、「2日おきが目安。週1〜2回だと採り遅れが出やすい作物です」と表示します（収穫期に入っている間だけ）。

### 実施日

すべての完了画面と「まとめて見回り済みにする」に、実施日（今日・昨日・日付を選ぶ）があります。普段は「今日」のまま1タップで完了できます。選んだ日付が保存され、次の作業の計算（間引き・次の収穫など）もその日から行います。実施日は事実なので **今日より先の日付は選べません**（予定は作付けの予定日として別に持ちます）。

## 9. 表示（ライト／ダーク）

設定タブの「表示」で、**自動／ライト／ダーク** を選べます。「自動」はスマホ本体の設定に合わせます。明るい屋外ではライトが読みやすいです。

- この設定は **端末ごと** で、スプレッドシートには同期しません（夫婦で別の表示にできます）
- ライト表示の補助文字・線・「もうすぐ」の色を濃くして、直射日光の下でも読みやすくしました（v4.3）
